## Статус исследования

| Компонент | Подтверждённый результат |
| --- | --- |
| Научная рукопись | Шесть разделов: введение, анализ работ, постановка задачи, методы, эксперименты, заключение; PDF собирается через GitHub Actions |
| Исходная НИР | CPU-прототип tiny-gpt2: три логических Ray-узла в Docker на **одной физической машине**; демонстрация генерации и исходная оценка обмена |
| Новый исследовательский модуль | Независимая реализация на Python с тремя Ray Actor-процессами **одного Ray-узла** в GitHub-hosted Linux CPU |
| Обработка логитов | Распределённые режимы D0–D3; монолитные контроли B0 и B1 |
| Собственные нагрузки | **144 сценария** на основе **12 исходных текстовых шаблонов** и комбинаций длин входа/ответа |
| Основная серия | **2160 измерений** tiny-gpt2; совпадение генерируемых токенов с эталоном во всех запусках |
| Дополнительный монолитный контроль | **1296 измерений** B0/B1/D3; D3 медленнее равноценно оптимизированного B1 на данном стенде |
| Модель сложнее tiny-gpt2 | DistilGPT2 с **шестью Transformer-блоками**, распределёнными между тремя Ray Actors; проверено совпадение токенов |
| Математическая оптимизация | Динамическое программирование для выбора границ групп слоёв; проверка полным перебором и применение к DistilGPT2 с **синтетическим** профилем затрат |

**Это реальные экспериментальные результаты, но не доказательство ускорения распределённого инференса на физических серверах.** Все новые CPU-замеры сделаны в GitHub Actions на одной виртуальной машине; фактический TCP/IP-трафик не измерялся.

## Что показала практика

| Серия и режим | Медианная задержка на GitHub CPU |
| --- | ---: |
| Основная серия tiny-gpt2: D0, возврат полных логитов | 178,48 мс |
| Основная серия tiny-gpt2: D3, локальный выбор токена | 71,36 мс |
| **Отдельная контрольная серия**: B1, оптимизированный монолит | **6,15 мс** |
| **Та же контрольная серия**: D3, оптимизированное распределённое выполнение | **43,95 мс** |

Медианы **разных серий нельзя напрямую сопоставлять**, поскольку они выполнены в отдельных запусках. Сравнение B1 и D3 корректно лишь внутри одной контрольной серии. Уменьшение тензоров объясняет не весь эффект: в D2/D3 одновременно сокращаются вычисления выходной проекции.

Для DistilGPT2 проверена работа **групп настоящих Transformer-слоёв** на трёх исполнителях и корректность двух разбиений. Профиль скоростей для динамического программирования синтетический: выбранное разбиение доказано оптимальным в заданной модели, а не на настоящих неоднородных серверах.

## Повторение проверок

Для сборки статьи локально нужен установленный Tectonic:

```bash
make article
python3 scripts/check_manuscript.py
```

Для автономных тестов экспериментальных компонентов требуется Python 3.11 и зависимости из [research/requirements.txt](research/requirements.txt). На Linux CPU:

```bash
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r research/requirements.txt
python -m unittest discover -s research/tests -v
python -m research.runner --model sshleifer/tiny-gpt2 --limit 4 --repeats 2 --output research/results/pilot
```

Полный прогон всех сценариев (ресурсоёмкий):

```bash
python -m research.runner --model sshleifer/tiny-gpt2 --limit 0 --repeats 3 --output research/results/full
```

На macOS Apple Silicon не используйте Linux-индекс PyTorch; инструкции установки и ограничения описаны в [research/README.md](research/README.md). Полный набор запусков и сохранённых данных не означает, что эксперименты уже повторены на MacBook.

## Важные границы и происхождение исходников

- Исходная НИР и новая исследовательская реализация — **разные проекты**: код первоначального `distributed-llm-ray-nir` не был перенесён в данный форк; новый модуль воспроизводит описанную архитектуру независимо.
- Модель tiny-gpt2 содержит два Transformer-блока; шестислойная **DistilGPT2** проверена в отдельных небольших сериях. GPT-2 124M, KV-cache, параллельная конвейерная обработка многих запросов и эксперименты на физических независимых серверах не выполнены.
- `payload_bytes` — байты логического массива на границе последнего исполнителя, **не** измеренный TCP/IP-трафик.
- Набор из 144 строк — **144 конфигурации нагрузки**, а не 144 независимо написанных текста и не обучающий корпус.
- Тексты кода, параметры и результаты доступны для воспроизведения. Научная оценка ограничена проверенными режимами и конкретной экспериментальной средой.

Оригинальный класс `misisarticle.cls` и файл `LICENSE` сохранены без изменений. `CHANGELOG.md` отделяет историю преподавательского шаблона от развития этой работы.
